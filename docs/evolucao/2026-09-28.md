## Bug encontrado e corrigido: IDOR — is_staff vê combos inativos de outro tenant [P2]

**Tipo:** P2 — cross-tenant info-disclosure de dados de catálogo (rascunhos de menu,
produtos fora de temporada) de outro restaurante. Não expõe PII nem dados financeiros,
mas viola a separação de tenants.

### Causa raiz

**Arquivo:** `apps/stores/api/views/product_views.py` — `StoreComboViewSet.get_queryset()` linha ~443

```python
# ANTES (BUG):
is_admin = self.request.user.is_authenticated and (
    self.request.user.is_staff or self.request.user.is_superuser
)
```

Convenção do projeto (CLAUDE.md, `apps/core/permissions.py:284`):
> "Nem is_staff nem is_superuser concedem acesso cross-tenant. Acesso vem de vínculo."
> is_staff abre o /admin do Django — não é bypass de isolamento de tenant.

Qualquer conta com `is_staff=True` mas sem vínculo real com a loja conseguia:
```
GET /api/v1/stores/combos/?store=<loja-vítima-uuid>
                 → combo ativo + combo inativo (IDOR)
GET /api/v1/stores/combos/?store=<loja-vítima-uuid>&is_active=false
                 → apenas combos inativos (IDOR)
```

**Bônus descoberto pelos testes:** dono da loja que NÃO tem `is_staff=True` também
não conseguia ver os próprios combos inativos no painel. A `is_admin` check
privilegiava `is_staff` ao invés de verificar vínculo real. O fix corrigiu ambos.

### Correção

```python
# DEPOIS (FIX):
user = self.request.user
is_admin = False
if user.is_authenticated:
    if user.is_superuser:
        is_admin = True
    elif store_slug or store_param:
        from apps.core.permissions import accessible_store_ids
        is_admin = queryset.filter(store_id__in=accessible_store_ids(user)).exists()
```

- **is_superuser:** bypass global — vê inativos de qualquer loja (correto, intencional)
- **Dono / StoreTeamMember:** `accessible_store_ids` retorna os IDs da loja do vínculo →
  `is_admin = True` → vê inativos da própria loja (regressão do dashboard corrigida)
- **is_staff sem vínculo:** `accessible_store_ids` não inclui a loja → `.exists() = False` →
  `is_admin = False` → combo inativo filtrado (IDOR bloqueado)
- **Anônimo / sem store_param:** `is_admin = False` → apenas combos ativos
