## Bug encontrado e corrigido: IDOR — is_staff vê ProductTypes inativos de outro tenant [P2]

**Tipo:** P2 — cross-tenant info-disclosure de dados de catálogo (tipos de produto
rascunhados, categorias fora de temporada) de outro restaurante. Mesmo padrão raiz
do bug de combos corrigido em 2026-09-28 (PR #380).

### Causa raiz

**Arquivo:** `apps/stores/api/views/product_views.py` — `StoreProductTypeViewSet.get_queryset()` linha ~522

```python
# ANTES (BUG):
if self.action == 'list' and not self.request.user.is_staff:
    queryset = queryset.filter(is_active=True)
```

Convenção do projeto (CLAUDE.md, `apps/core/permissions.py:284`):
> "Nem is_staff nem is_superuser concedem acesso cross-tenant. Acesso vem de vínculo."
> is_staff abre o /admin do Django — não é bypass de isolamento de tenant.

Qualquer conta com `is_staff=True` mas sem vínculo real com a loja conseguia:
```
GET /api/v1/stores/product-types/?store=<loja-vítima-uuid>
                 → tipo ativo + tipo inativo (IDOR)
GET /api/v1/stores/product-types/?store=<loja-vítima-uuid>&is_active=false
                 → apenas tipos inativos (IDOR)
```

**Bônus descoberto pelos testes:** dono da loja SEM `is_staff=True` também não
conseguia ver seus próprios tipos inativos no painel (regressão). O fix corrigiu
ambos os lados.

### Correção

```python
# DEPOIS (FIX):
user = self.request.user
is_admin = False
if user.is_authenticated:
    if user.is_superuser:
        is_admin = True
    elif store_slug or store_param:
        from apps.core.permissions import accessible_store_ids
        is_admin = queryset.filter(store_id__in=accessible_store_ids(user)).exists()
if self.action == 'list' and not is_admin:
    queryset = queryset.filter(is_active=True)

# Filtro explícito ?is_active=true|false (painel usa este param).
# Admins podem pedir inativos; para os demais o filtro acima já restringe.
is_active_param = self.request.query_params.get('is_active')
if is_active_param is not None:
    wants_active = is_active_param.lower() in ('1', 'true', 'yes')
    queryset = queryset.filter(is_active=wants_active)
```

- **is_superuser:** bypass global (intencional)
- **Dono / StoreTeamMember:** `accessible_store_ids` retorna os IDs do vínculo →
  `is_admin = True` → vê inativos da própria loja (regressão corrigida)
- **is_staff sem vínculo:** `accessible_store_ids` não inclui a loja → `is_admin = False` →
  tipo inativo filtrado (IDOR bloqueado)
- **Anônimo / sem store_param:** `is_admin = False` → apenas tipos ativos
