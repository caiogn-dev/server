## Bug corrigido — P2 · Tenant isolation

### `adotar` ingrediente recusava StoreTeamMember com 403

**Arquivo:** `apps/nutrition/api/views.py:92`

#### Problema

A action `POST /api/v1/nutrition/ingredients/{id}/adotar/` verificava o acesso
à loja com uma query direta:

```python
Store.objects.filter(Q(pk=loja_id) & (Q(owner=request.user) | Q(staff=request.user)))
```

Essa check cobre apenas **owner** e o campo M2M legado **staff**. Ignora
`StoreTeamMember` — o modelo moderno de papéis, usado desde o sistema de
gerentes/operadores. Um usuário adicionado como gerente pela tela de equipe
recebia 403 ao tentar adotar ingredientes para a loja dele.

O resto da API de nutrição (receitas, perfis, custos) usa `user_can_access_store()`
ou `accessible_store_ids()`, que incluem `StoreTeamMember`. Só o `adotar` ficou
com a check manual e incompleta.

#### Impacto

Gerentes e operadores cadastrados via `StoreTeamMember` não conseguiam:
- Copiar ingredientes da base pública para a loja
- Revisar alergênicos (fluxo de desbloqueio da etiqueta ANVISA)
- Reeditar um ingrediente adotado (adotar novamente para atualizar)

#### Correção

Substituiu a query manual por `user_can_access_store(request.user, loja_alvo)`,
que é a régua única do projeto e inclui os três caminhos de acesso: owner,
staff M2M e StoreTeamMember ativo.

#### Teste adicionado

`test_membro_da_equipe_pode_adotar` em `apps/nutrition/tests/test_adotar_ingrediente.py`:
cria um `StoreTeamMember.Role.MANAGER`, tenta adotar com ele — esperava 201,
recebia 403 antes da correção.
