## Fix aplicado: logger.error com {e} em langchain_service.py [P1]

**Tipo:** P1 — credenciais de API LLM no campo `message` de logs → Sentry/GlitchTip.

**Vetor:** `apps/agents/services/langchain_service.py` tinha 14 handlers `except Exception as e:`
com `logger.error(f"...{e}")`. Exceções HTTP do OpenAI/Anthropic/Kimi incluem no `str(e)` o texto
completo da resposta de erro — que pode conter o token Bearer, a chave de API ou URL autenticada.
Com `f-string + logger.error`, esse texto vai para o campo `message` do LogRecord e é indexado como
texto livre pesquisável no Sentry/GlitchTip.

**Correção:** todos os 14 `logger.error(f"...{e}")` convertidos para `logger.exception("mensagem
em pt-BR")` (que usa `exc_info=True` e coloca o traceback em campo separado). `BaseAPIException`
em `process_message` passou a usar mensagem genérica sem `str(e)`. Yield de erro em
`process_message_stream` (código morto) também corrigido preventivamente.

**Testes:** `apps/agents/tests/test_langchain_logger_str_exc.py` — 7 `SimpleTestCase`, RED→GREEN.

**PR:** `bot/server-2026-10-20-langchain-logger-str-exc`
