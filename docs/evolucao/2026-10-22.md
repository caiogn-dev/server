## Bug corrigido — P2 · Info-disclosure em logs de pagamento

### `payment_views.py` — 6 `logger.error(f"...{e}")` + 1 `logger.error('%s', e)` no callback MP OAuth

**Arquivo:** `apps/stores/api/payment_views.py`

#### Problema

`StorePaymentViewSet` tinha seis actions com o mesmo padrão inseguro:

```python
# ANTES (bug):
except Exception as e:
    logger.error(f"Error creating payment: {e}")    # linha 271
    logger.error(f"Error processing payment {payment.id}: {e}")  # 295
    logger.error(f"Error confirming payment {payment.id}: {e}")  # 320
    logger.error(f"Error failing payment {payment.id}: {e}")     # 346
    logger.error(f"Error cancelling payment {payment.id}: {e}")  # 364
    logger.error(f"Error refunding payment {payment.id}: {e}")   # 389
```

E o callback MP OAuth tinha:

```python
# ANTES (bug):
except Exception as e:
    logger.error('[MP OAuth] troca de código falhou para %s: %s', slug, e)  # 195
```

**Risco concreto:** O SDK do Mercado Pago levanta `requests.exceptions.HTTPError` cuja
`str(e)` inclui o corpo completo da resposta HTTP de erro. Em chamadas de criação
e processamento de cobrança, esse corpo pode conter o `access_token` do lojista
(presente nos cabeçalhos da requisição falha). Em chamadas de troca de código OAuth,
pode conter o `client_secret` da plataforma ou o authorization code.

Ao usar `f"...{e}"`, o `str(e)` é escrito diretamente no campo `message` do log
record — o mesmo campo que textos livres e que ferramentas de aggregação de log
(Sentry, CloudWatch, Datadog) usam para buscas e alertas. Redatores configurados
por **campo** (`access_token`, `Authorization`) não atuam sobre `message`.

#### Correção

```python
# DEPOIS:
except Exception:
    logger.exception('Erro ao criar pagamento')
    logger.exception('Erro ao processar pagamento %s', payment.id)
    logger.exception('Erro ao confirmar pagamento %s', payment.id)
    logger.exception('Erro ao registrar falha de pagamento %s', payment.id)
    logger.exception('Erro ao cancelar pagamento %s', payment.id)
    logger.exception('Erro ao realizar estorno do pagamento %s', payment.id)

# OAuth:
except Exception:
    logger.exception('[MP OAuth] troca de código falhou para %s', slug)
```

`logger.exception` registra o traceback e str(e) no campo `exc_info`
(separado de `message`), onde scrubbers de campo operam corretamente.
