## Bug corrigido — P2 · Info-disclosure: str(exc) em logs do caminho de pagamento MP

### `payment_service.py` + `webhooks.py` — 3 handlers expõem exceção bruta no campo message

**Tipo:** P2 — A SDK do Mercado Pago lança exceções cujas representações textuais
incluem o corpo da resposta HTTP da API MP. Respostas de erro da API MP frequentemente
contêm o `access_token` do vendedor no campo de auditoria ou em mensagens como
`"invalid access token"`. Colocar `str(exc)` no campo `message` do log record
(via f-string) ignora qualquer scrubber de campo configurado no Sentry/CloudWatch/
Datadog — que trabalham sobre `exc_info`, não sobre `message`.

**Arquivos corrigidos (2, 3 instâncias):**

1. `apps/stores/services/payment_service.py`
   - `_process_mercadopago` (linha ~162): `self.logger.error(f"Error processing Mercado Pago payment: {e}")` → `self.logger.exception("Erro ao processar pagamento MP — payment_id %s", payment.payment_id)`
   - `_refund_mercadopago` (linha ~292): `self.logger.error(f"Error processing Mercado Pago refund: {e}")` → `self.logger.exception("Erro ao realizar estorno MP — payment_id %s", payment.payment_id)`

2. `apps/stores/api/webhooks.py`
   - `_send_payment_confirmation_whatsapp` (linha ~424): `logger.error(f"Failed to send WhatsApp confirmation: {e}", exc_info=True)` → `logger.exception("Falha ao enviar confirmação WhatsApp — pedido %s", getattr(order, 'order_number', '?'))`

**Padrão do fix:** `except Exception as e:` → `except Exception:` + `logger.exception("mensagem fixa %s", id_sem_segredo)`. O traceback fica em `exc_info` (campo separado), onde scrubbers de campo operam. O campo `message` fica limpo.
